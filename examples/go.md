# Example: 「囲碁のゲームを作って」

## 想定する来訪者の言葉

> 囲碁のゲームを作って

## 解析の例

```json
{
  "goal": "その場で囲碁を遊びたい",
  "audience": "来訪者とスタッフの2人",
  "category": "game",
  "recipe_file": "recipes/game.md",
  "build_path": "codegen",
  "mvp": {
    "inputs": ["9路盤の交点を選ぶ", "パス"],
    "outputs": ["盤面", "次の手番", "捕獲した石の表示"],
    "primary_action": "交互に石を置く",
    "success_check": "合法手で石が増え、ターンが切り替わる"
  },
  "assumptions": ["9路盤", "同一端末で2人対戦", "黒が先手", "日本語UI"],
  "question": {
    "ask": false,
    "text": null,
    "options": [],
    "default_option": null
  },
  "scope_note": "対戦AIは付けない。スコア判定等は実装した場合のみ表示"
}
```

※ これは唯一の正解ではない。事前に簡単な対戦AIを利用できる場合は「1人／2人」の質問を出してもよい。

## 来訪者向けの最初の説明

> まずは9路盤で2人対戦できる囲碁を作ります。石を置くところから試してみましょう。

## 画面イメージ

```text
┌──────────────────────────────┐
│ 囲碁 9×9       ● 黒の番      │
├──────────────────────────────┤
│                              │
│        ・ ・ ・ ・ ・           │
│        ・ ○ ● ・ ・           │
│        ・ ・ ● ・ ・           │
│        ・ ・ ・ ・ ・           │
│          [実際の9路盤]        │
│                              │
├──────────────────────────────┤
│ [パス]           [やり直す]  │
│ 基本ルール対応状況を明示     │
└──────────────────────────────┘
```

上は仕様の参考図であり、実際のレンダリングそのものではない。

## ルールの最小検証

1. 何もない交点へ黒石を置くと、その位置に黒石が表示される。
2. 次の手番が白になり、白石を置ける。
3. 石のある交点への重複着手は拒否される。
4. **捕獲ルールを実装した場合**、呼吸点を失った相手の連結石群が盤面から消える。
5. **自殺手禁止を実装した場合**、自分の石群がすべて呼吸点を失う着手は拒否される。ただし相手を取って呼吸点ができる合法手を拒否しない。
6. **コウを実装した場合**、直前の局面へ即座に戻す反復手が拒否される。
7. パスでき、連続パスなら対局終了画面が表示される（終局判定を実装した場合）。
8. リセットで空の9路盤と黒番に戻る。

## 必ず区別する範囲

- 盤面への交互着手だけなら「囲碁盤の基本操作版」。
- 捕獲・反復禁止・パスなどまで動くなら「基本ルール対応の囲碁デモ」。
- 正確な地合い計算・コミ等が未実装なら「勝敗の自動計算は未実装」と表示。

## 追加指示の例

> もっと本物の碁盤っぽい木目調にして。

**期待すること**：盤面の背景・罫線・石の見た目を更新し、石を置く機能は壊さない。単なる画像への差し替えでクリックが効かなくなるのは失敗。

## タイムアウト時の縮小方針

「ルール全部を満たす囲碁」を無理に完成宣言しない。2人が交互に置ける盤面を優先し、未対応ルールを明記して出す。
