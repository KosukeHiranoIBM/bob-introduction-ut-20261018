# Questions — 聞くのは原則0問、必要でも1問

## 基本原則

**質問は仕様書の穴埋めではなく、完成物の体験を大きく変える場合だけに使う。** 多くの曖昧さは既定値で補い、すぐ制作へ進む。

## 1問だけ聞いてよい条件

以下をすべて満たす場合だけ聞く。

1. 答え次第で**主要機能・制作経路・体験**が大きく変わる。
2. どちらか一方に勝手に決めると、期待外れになる可能性が高い。
3. **2〜3択**で10秒程度で回答でき、専門知識を要しない。

例：

| 依頼 | 質問する？ | 理由／質問例 |
|---|---|---|
| 「囲碁を作って」 | 場合による | 「1人で遊ぶ／2人で遊ぶ」の差は大きい。コンピューター対戦を実装できないなら2人用を既定にし、無理な選択肢は出さない |
| 「家計簿を作って」 | いいえ | 円表示、サンプル支出、カテゴリ別集計から始められる |
| 「売上ダッシュボード」 | 原則いいえ | 架空の月次売上から画面を作れる |
| 「クイズを作って」 | 場合による | 「遊ぶクイズ／問題を作る道具」は用途が異なる。ただし文脈から推定できれば聞かない |
| 「TODOアプリ」 | いいえ | 追加・完了・削除が既定のMVP |

## 質問文のフォーマット

- 1文 + 選択肢2〜3個。選択肢は生活者にわかる表現。
- システム上可能な選択肢だけを提示する。
- 既定値を用意し、無回答・曖昧回答でも制作を進める。
- UI上は可能ならボタン／チップ／ラジオで回答させる。

例：

> どちらで遊びたいですか？
> ① 友達と2人で遊ぶ（おすすめ） ② コンピューターと遊ぶ

**注意：** ②を表示するのは簡単なAI対戦等が実装可能な場合だけ。できなければ実現可能な選択肢に置き換えるか、質問なしで2人用を制作する。

## 質問しない項目

基本配色、フォント、グラフ種類、初期サンプル数、細かなゲーム難易度、DB、クラウド、フレームワーク、リッチな機能の要否は聞かずに合理的に決める。来訪者が明示的に指定した項目は尊重する。

## 例外

本人確認、個人情報、外部送信、課金、不可逆操作に必要な許可は、**「質問1問」の演出制約とは別**。その許可がないなら操作を実行せず、架空データでのローカル実演に切り替える。

## 内部の判断文（来訪者には不要）

```text
重大な分岐があるか → ない：質問0で制作
                    → ある：選択肢が実現可能か
                           → 可能：1問だけ聞く
                           → 不可能：実現可能な既定値で制作し制約を伝える
```
