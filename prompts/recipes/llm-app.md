# Recipe — LLMアプリ（テキスト・音声AIとの対話）

## 適用条件

- 「AIとおしゃべりできるアプリ」「質問に答えるチャット」「リアルタイムで声で会話」「AI相談室」など。
- `prompts/openai-integration.md` を**必ず追加**で読む。モデルや外部通信の許可は `demo-config.md` に従う。

## 要求の切り分け

- **文字で会話**：テキスト入力 → 送信 → サーバー経由の OpenAI Responses API → 返答を描画。目標は**実際にAIが返す**こと。
- **マイクで会話・音声で返答**：開始ボタン → マイク許可 → 短命シークレット → WebRTC Realtimeセッション → 発話／返答。マイクが不要なら誤って音声機能を作らない。
- 「リアルタイムでおしゃべり」だけで音声か文字か曖昧なときは質問を最大1問：`「文字でチャット」「声で話す」`。回答なしの既定値は文字チャット。
- 既存の家計簿や発想支援アプリにAIの解説機能を付ける場合、元レシピを主とし、このレシピは必要な部分だけ追加適用する。

## 展示向け画面要件

- 初期画面に明確なタイトル「AIと話してみよう」など。
- 発話／入力欄と目立つ送信ボタンまたはマイク開始ボタン。
- AIの返答を大きなチャットバブルに表示し、入力中・接続中・エラーを区別。
- サンプル質問チップを2〜3件表示（例：「今日の献立」「なぞなぞ」「旅行の相談」）。
- 「会話をリセット／次の来訪者」ボタンを設けて直前の会話を消去。
- `「入力した内容はAIサービスへ送信されます。個人情報を入力しないでください」` 等の短い注意文を表示。

## 最小実装と受け入れ条件

### テキストMVP（優先）

1. ユーザーが1つ入力できる。
2. `POST /api/chat` など自分のサーバーへ送信し、サーバーが実際に OpenAI APIを呼ぶ。
3. モデル応答が会話欄に描画される。架空の固定応答は禁止。
4. 通信中は二重送信しない。API失敗時はエラー表示。
5. APIキーはブラウザへ返さず、`.env` を読み込むサーバープロセスだけが利用する。

### 音声MVP（機材条件を満たす場合）

1. 開始時にマイク権限を確認する。
2. 自社サーバーから短期クライアントシークレットを安全に取得。
3. Realtime APIとのWebRTC接続を確立。
4. 人が話す→AIが音声で答えることを**実機で**確認。
5. 明確な終了ボタン、マイク停止、セッションリセット。

## フォールバック

- キー・通信・モデルアクセスが不足：UIは作れても **「AI未接続の画面案」** と明記する。固定返答を「AIと会話できた」と見せない。
- 会場の音響・ネットワーク条件が悪い：文字チャットの実接続を優先し、音声は未実装として区別する。
- 超大規模な要求：会話画面と単一の動作するAPI連携までに限定する。

## 変更指示の例

- 「猫のキャラクターが話しているようにして」→ 表示や見た目を変更（音声要件とは別）。
- 「日本語と英語を切り替えたい」→ 表示言語／プロンプトを追加し、既存のAPI呼び出しを維持。
- 「声をもう少し明るく」→ Realtimeの対応する音声設定を確認して変更、実機で聞き直す。
