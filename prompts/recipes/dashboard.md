# Recipe: Dashboard — 家計簿・数字・グラフ・分析

## 対象

家計簿、売上分析、アクセス集計、アンケート結果、支出管理、KPIボードなど。**データ → 集計 → 視覚化**が体験の主役。

## 優先する完成条件

- 大きな主要数値（合計など）と意味のあるグラフを表示。
- 元データと可視化の間で計算が一致。
- 少なくとも1件追加／条件変更して、数値とグラフが同時に更新。
- 実データがない場合は、目に見える `サンプルデータ` 表示を付ける。

## 最小データモデル

題材に合わせるが、典型例：

```text
record = { id, date, label, category, amount }
summary = group_by(category, sum(amount))
monthly_total = sum(amount in selected_month)
```

- 表示通貨や単位は依頼・言語に合わせる。日本の家計簿なら初期値は円。
- 分母0、負の値、入力の空欄、異常値への最低限の入力チェックをする。
- グラフは**実際の内部データ**から描画する。見た目だけの偽グラフを避ける。

## 最初に作る画面

1. 大きな集計カード（例：「今月の支出」「先月比」※先月比は先月データがあるときのみ）。
2. カテゴリ別棒グラフまたはドーナツ（読みやすい方を選ぶ）。
3. 直近の記録一覧。
4. 金額・カテゴリ・日付など最小限の追加フォーム。
5. 追加後の即時集計と、わかるフィードバック。

## 家計簿の既定設定

- 架空のカテゴリ：食費、住居、交通、趣味、その他。
- 架空の取引履歴を数件表示し、`サンプル` を画面で明示。
- **主要操作**：支出を1件追加すると、合計・カテゴリ別グラフ・履歴の全てが更新される。
- 銀行API接続、OCR、ログイン、本番DB、複数端末同期などは最初から作らない。
- 保存がないなら更新後に消えることを隠さない。利用可能・許可済みなら localStorage 等を使ってよい。

詳しい受入条件は `examples/household-budget.md`。

## テスト

- 初期データの合計が個別明細の合計と一致。
- 例えば `500円` を食費に追加すると、総額と食費がともに500円増える。
- 追加した明細が表示される。
- 不正な数値を拒否する。
- 0件でも壊れない。

## 追加指示例

「円グラフにして」「収入も見たい」「カテゴリを増やして」「先月と比べて」。要求に必要なデータがないときは架空サンプルを明示して補う。
