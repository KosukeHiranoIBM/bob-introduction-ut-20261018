# Recipe: Game — ゲーム・パズル・対戦

## 対象

囲碁、オセロ、三目並べ、盤上ゲーム、パズル、簡単なアクション／クイズゲームなど、**利用者の操作でゲーム状態が変化するもの**。

## 優先する完成条件

- 最初の画面で遊ぶ場所がわかる（盤面、カード、スコアなど）。
- 主操作（着手、移動、カード選択、回答）が実際に反応する。
- ゲームの状態（手番、正誤、得点、終了条件など）が内部状態と一致する。
- リセットで最初から遊べる。

## 要求の具体化

- **プレイ人数**：原則最も簡単で遊べる人数を既定に。1人用AIがないのにAI対戦をうたわない。
- **盤面の大きさ**：デモ映えし、実装しやすいサイズを採用。
- **ルール**：完全なルールの再現に時間がかかるなら、対応するルールを明記した「ミニ版」に縮小。
- **入力**：クリック／タップを基本にする。キーボードのみを強制しない。
- **結果**：直前の操作が盤面／ラベル／スコアへ明確に反映される。

## 最初に実装するもの

1. 状態データ（盤面、現在の手番、ゲーム結果）。
2. 主操作のイベントとルールチェック。
3. 盤面等の大きな視覚表示。
4. 手番・エラーの短いメッセージとリセット。
5. 余裕があれば undo、アニメーション、効果音等（演出は後回し）。

## 囲碁の例（来訪者から追加指定がない場合）

**第一候補：9路盤・2人対戦・同一端末。** 以下のどこまで正しく作れたかを検証し、できていないルールを隠さない。

- 黒から交互に石を置く。盤外・既存の石への着手は不可。
- 連結した石群の呼吸点を判定し、呼吸点がなくなった相手の石群を取る。
- 自殺手の禁止を判定する（使用するルールで例外があるなら明示）。
- 単純コウなどの反復禁止は、実装したルール範囲で明示・テストする。
- パス、連続パスによる終局、リセットを設ける。
- 地の計算・コミ・厳密な勝敗判定を未実装なら、**勝者を自動判定したふりをしない**。終局画面に「得点計算は未実装」と表示。

もし上記すべてを短時間で確認できないなら、二人が交互に石を置ける「囲碁盤の基本操作版」を先に完成させ、取り・コウ等の未実装部分を明示する。囲碁のルールを省略したゲームを正式な囲碁完成品として見せない。

詳しい受入条件は `examples/go.md`。

## 画面の優先順位

1. 盤面やプレイ領域を最も大きく。
2. 手番・状態を大きな短文で。
3. 1〜2個のアクション（パス、リセット等）。
4. 説明と詳細ルールは補助領域に。

## 最小テスト例

- 不可能な位置を選んでも盤面が壊れない。
- 1手で手番が切り替わる。
- ルール上取れる／正解になる場面では状態が正しく変わる。
- リセット後に初期状態へ戻る。

## 追加指示例

「盤面を大きく」「木目調にして」「手番表示を追加して」「undo を入れて」。変更したら、着手とリセットを再確認する。
