# Visual Design — 展示会で「一目で伝わる」UI のルール

## デザインの目的

来訪者は数秒で結果を見る。見た目は装飾ではなく、**何ができたかを直感的に伝える説明装置**である。機能の完成度を偽るための演出に使わない。

## ファーストビューの要件

- 一目でわかる**短い名前／大きい主役**を置く。
- 画面中央〜上部に、ゲーム盤・主要グラフ・大きな入力欄・生成カードなどの**主役コンポーネント**を置く。
- 来訪者が押せる主要ボタンは目立つ位置に1つ。押したら状態が視覚的に変わる。
- 何も入力しない状態でも、架空の初期データやわかりやすい空状態で体験が想像できる。
- 大型ディスプレイで読める文字サイズと明瞭なコントラストにする。小さな文字や密集表は避ける。
- 起動直後に致命的なエラーや意味のないローディングだけを見せない。準備中なら現在の工程を短く示す。

## 推奨の見せ方（用途ごと）

| 用途 | 一目で伝わる主役 | 実際の操作で変わるもの |
|---|---|---|
| ゲーム | 大きな盤面／キャラクター／スコア | 盤面、ターン、結果 |
| 集計／家計簿 | 大きな数字＋グラフ＋データ一覧 | 合計、棒、割合、履歴 |
| 管理アプリ | カード／一覧＋ステータス | 追加、完了、フィルタ結果 |
| ジェネレーター | 条件入力＋生成されたカード | 生成結果、バリエーション |
| ワークフロー | 横または縦のフローチャート | 進行中のステップ、承認結果 |
| 未対応／構想 | 大きなアプリ画面案＋機能一覧 | 可能なら一部のローカル操作。未実装を明示 |

## レイアウト

- 1画面を原則とする。情報過多より余白を優先。
- 主役と補助情報の強弱を明確にする（大きな数字、小さなラベル）。
- 画面幅が狭くなっても、主要操作を隠さず縦並びにできるようにする。
- ダーク／ライトはブランドに合わせて統一。無闇に多数の色を使わない。
- アイコンはラベルを補助するものとして使い、アイコンだけで意味を伝えない。
- アニメーションは短く控えめにし、操作結果の伝達に使う。常時激しく動かさない。

## 色と文字

- 背景・カード・文字・主要アクション・成功／注意の役割を分ける。
- テーマの主要カラーは1〜2色、データ可視化の分類色は必要数に限定する。
- 色の違いだけでステータスを表さず、アイコンやテキストも使う。
- ブランド設定が提供されたら尊重する。未指定なら読みやすくクリーンなデザインを選ぶ。
- WCAGの考え方を参考にコントラストとキーボード操作を意識する。ただし未検証なら準拠を断言しない。

## データの見せ方

- 数字には単位・通貨・期間を付ける（例：`今月の支出 ¥128,450`）。
- 架空データには画面上で `サンプルデータ` と表示する。
- 数値・ラベル・グラフの間で整合を取る。カテゴリ割合の合計が100%にならない場合は「その他」を用いるか理由を示す。
- 操作による更新は同じ画面で即時反映する。誤差や非同期処理がある場合は状態を表示する。

## デモの二画面運用（可能なら）

- **操作用画面**：ユーザー入力、AIの短い工程表示、実行結果、エラー。
- **大画面**：プレビューと「操作してみる」案内。長い技術ログは不要。
- 一画面しかなければ、プレビューを大きく、チャット／ログは折りたたむ。

## やらないこと

- 無意味なチャートやランダムな数値で豪華さを演出する。
- 未接続ボタンを多数並べる。
- 実データのように見せかけたサンプルを使う。
- コードを大画面の主役にする（来訪者がコードを求めた場合を除く）。
- 画像生成だけでプログラムが動いたように見せる。
