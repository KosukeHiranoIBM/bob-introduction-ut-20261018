# Quality Gate — 完成と呼んでよいかを判定する

## 最低限の合格条件

生成した成果物について、実際に確認できる項目だけをチェックする。

### A. 内容

- [ ] 来訪者の依頼と成果物が対応している。
- [ ] 主要な1操作が定義されている。
- [ ] その操作で何が変わるか、画面上でわかる。
- [ ] 仮定（9路盤、架空データなど）と未実装の範囲が不自然に隠れていない。

### B. 動作（ツールがある場合）

- [ ] プレビューが開く／必要なビルドが通る。
- [ ] 主要ボタンや入力を1回操作できる。
- [ ] 操作前後の状態・値が正しく変わる。
- [ ] 明らかなコンソールエラー／例外がない。
- [ ] 重要な操作を2回繰り返しても破綻しない。
- [ ] 追加指示で再生成した場合、もとの主要機能が壊れていない。

### C. 見た目

- [ ] ファーストビューで用途と主役がわかる。
- [ ] 主要ボタン・メッセージ・数値が読める。
- [ ] グラフと数字が同じデータを参照する。
- [ ] 架空データ／コンセプトはその旨の表示がある。
- [ ] モバイル／狭い画面でも主要操作が可能（確認できる範囲）。

### D. データ・安全

- [ ] 不要な外部APIや機密情報を使っていない。
- [ ] 生成コードは許可された隔離環境でのみ実行している。
- [ ] データの保存、送信、削除などを実施したと偽っていない。
- [ ] 外部連携が未実装なら明示されている。

## 失敗した場合の順序

1. 最も目立つ不具合（画面が開かない／主操作が動かない）を優先して直す。
2. 設定された再試行上限内で1回程度の修正→再確認を行う（上限は運営者のタイムアウト設定に従う）。
3. 直らなければ機能を狭め、動く最小部分を出す。
4. それも無理なら `fallback.md` に従い、**コンセプトプレビュー**として正直に出す。

## 結果の表示ルール

次のいずれかを採用する。

| ラベル | 適用条件 | 表示例 |
|---|---|---|
| 動作確認済みプロトタイプ | 実際に起動し主要操作を確認 | 「支出を追加すると合計が更新されます」 |
| 未検証プロトタイプ | ソースを生成したが動作を確認できない | 「コードを生成しました。起動動作は未検証です」 |
| コンセプトプレビュー | 画面案・動作説明が主体 | 「こちらは完成イメージです。外部連携は未実装です」 |

## 運営者向け記録（任意）

`request / category / build_path / question_count / time_to_first_visual / time_to_interactive / validation_status / primary_action_pass / notes`

※ 実測できない時間は空欄にする。架空の速度や成功率を報告しない。
